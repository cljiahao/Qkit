# booths

## Purpose

Vendor booth list, the shared create/edit form and its building-block editors, and the server actions that persist a booth under plan entitlements.

## Contents

- `[boothId]/` — edit-booth page for one booth id, plus its printable QR sub-route.
- `actions.test.ts` — vitest suite (mocked Supabase chains, mocked `@/lib/paykit/client`, mocked `@/lib/printkit/client`) covering `saveBooth`'s entitlement enforcement: menu-item cap rejection, option-group cap rejection, silent stripping of `hours`/`stock` on a free-plan save, the active-booth cap (reject activating a 2nd booth) and its `neq` exclusion when re-saving the same booth; the paykit cutover (a set config writes the full config to paykit and only a `{kind}` marker to `booths.payment`, a null config clears the marker without calling paykit, a paykit rejection fails the whole save without writing the booth); printkit location sync (`print_enabled` lands on the row, `registerPrintLocation` is called with `active: true`/`false` to match, and a rejected or `ok:false` call never changes `saveBooth`'s own return value); `deleteBooth`'s own printkit deregistration (`registerPrintLocation` called with `active: false` and the deleted booth's name/id after a successful delete, and a rejected or `ok:false` call never changes `deleteBooth`'s own return value); and `toggleBoothActive`'s invalid-id rejection, unconditional allow when turning off, the same active-booth cap (and `neq` self-exclusion) when turning on.
- `actions.ts` — server actions: `deleteBooth(boothId)` hard-deletes a booth (cascades to its orders per migration 0009), RLS-scoped so a non-owner deletes zero rows, reclaims its Storage images via `removeBoothImages`, and best-effort deregisters the booth's printkit print location (`registerPrintLocation` with `active: false`) so a deleted booth doesn't linger as an active location on printkit's side — never blocks the delete itself; `regenerateShortCode(boothId)` calls the `regenerate_short_code` RPC to rotate the booth's QR token and revalidates the QR page; `saveBooth(input)` validates with `boothFormSchema`, re-checks entitlement server-side (menu-item cap, option-groups-per-item cap, strips `hours`/per-item `stock` for plans without `autoCloseHours`/`stockCaps`), enforces the free-tier single-active-booth cap via a count query, and — the paykit cutover — when `payment` is set, calls `upsertVendorConfig` (`@/lib/paykit/client`) with the full config, failing the whole save on a paykit error; it then inserts or updates the `booths` row with `payment` narrowed to a minimal `{kind}` marker via `paymentMarker` (not the full config — see the doc comment on why: `qkit.place_order`, migration 0056, still reads `booths.payment->>'kind'` to decide a new order's `payment_status`, and there is no SQL-side way to ask paykit instead) plus `requires_arrival_confirm`, `walkup_default`, and `print_enabled` (none entitlement-gated), and reclaims orphaned images (`orphanedImagePaths`) on update; after a successful save it best-effort calls `registerPrintLocation` (`@/lib/printkit/client`) with the booth's id/name and `print_enabled` as `active`, so printkit knows whether this booth's location should currently accept jobs — a failure there is logged and never turns the save into an error, same contract as `notifyPrintkit` in `src/app/o/[code]/actions.ts`. Both call sites share a `syncPrintLocation(vendorId, boothId, label, active, context)` helper, `context` only used to label its own error logs (`"saveBooth"`/`"deleteBooth"`). `toggleBoothActive(boothId, active)` is a lightweight sibling that flips only `is_active` — used by both the live board's quick pause `Switch` and this folder's `close-booth-control.tsx`, same active-booth cap check as `saveBooth` when turning on, always allowed when turning off.
- `booth-form.dom.test.tsx` — RTL tests for `BoothForm`'s walk-up-default `Switch` (every other subcomponent it composes is stubbed out — each already has its own dom test file): starts unchecked and submits `walkup_default: false` for a plain new booth, toggling it on submits `true`, `eventMode` pre-checks it and shows a "Recommended" badge (create flow only), an existing booth's saved `true` value round-trips on render, and toggling an existing booth's value off persists on save.
- `booth-form.tsx` — `BoothForm({ vendorId, entitlement, vendorSocialLinks, eventMode?, initial? })` client component: the single create/edit form driving `name`, `image_url`, `is_active`, `hours`, `menu_items`, `payment`, `social_links`, `print_enabled` state, composing `MenuEditor`, `WorkingHoursEditor`, `PaymentSection`, `PrintingSection`, `SocialLinksSection`, and an `ImageUploader` banner inside `Section` blocks. The layout is 3 grid items, not 2 (Name+photo/Hours/Order flow, then Menu, then Payment/Printing/Social links), so a single-column mobile view stacks Menu right after Hours instead of at the very bottom, while `md:`+ still lays out as two columns (Menu spans both rows on the right) — same visual grouping as before. Validates with `boothFormSchema` on submit (sanitizing half-filled option groups first), calls `saveBooth`/`deleteBooth`, and includes a "Danger zone" delete confirmation (`AlertDialog`) when editing. The "Hours & availability" section's active/inactive control differs by mode: a brand-new booth (no `initial.boothId`) gets a plain `Checkbox` (nothing to guard yet — it isn't live); an existing booth gets `CloseBoothControl` instead, a deliberately more guarded close path than the board's own pause switch. A separate "Order flow" `Section` (not nested under Hours — these toggles are about how an order is entered/prepped, not when the booth is open) holds two controls: a "Hold prep until the customer arrives" `Checkbox` drives `requires_arrival_confirm` ("scan-to-start" — for items made fresh per order, like ice cream, where prep can't start until the customer is actually at the counter): when on, `place_order` (migration 0064) inserts new orders at `'pending'` instead of `'preparing'`, and the order-status page shows an "I'm here, start my order" prompt (`OrderStatusPoller`'s pending branch, `confirmArrival`) instead of starting the clock immediately. Walk-up orders (`place_walkup_order`) are unaffected — a vendor keying in a counter order in person has no "customer arrives later" to wait for. Next to it, a "Default to walk-up order entry" `Switch` drives `walkup_default` (event-mode setup, migration 0080) — when on, the live board (`realtime-order-board.tsx`) auto-opens the walk-up dialog on load instead of the QR/menu-first presentation, for a one-off event where staff key in every order; the `eventMode` prop (set by `new/page.tsx`'s `?mode=event`) pre-checks this toggle and shows a small "Recommended" badge next to its label for a brand-new booth, but never overrides an existing booth's own saved value. A "Printing" `Section` renders `PrintingSection`, driving `print_enabled` (migration 0082) — this booth's opt-in to auto-print a label for every order via printkit; `saveBooth` best-effort registers/updates the booth's printkit location to match on every save. A "Social links" `Section` renders `SocialLinksSection`, letting this booth override the vendor's profile-level default links (`vendorSocialLinks`, read from `vendors.social_links` by the `new`/`[boothId]` pages) — off by default, so most booths just inherit the vendor's own links from `../profile`.
- `booth-list.tsx` — `BoothList({ booths })`: renders each booth as a `Ticket` card (banner image, name, Active/Paused/Off status pill, item count) with Edit / QR (`/dashboard/booths/{id}/qr`) / copy-order-link (`/o/{shortCode}`) actions.
- `close-booth-control.dom.test.tsx` — RTL tests for `CloseBoothControl`: the active state opens a confirm dialog and does nothing on a quick tap-and-release of the hold button; a full 3-second hold calls `toggleBoothActive(id, false)`, notifies the parent, and fires an undo toast whose own action reopens; a failed close/reopen shows an error toast without calling `onChanged`; the paused state reopens on a single instant click, no hold.
- `close-booth-control.tsx` — `CloseBoothControl({ boothId, boothName, isActive, onChanged })` client component: the guarded half of the booth open/close pair Manfred's fat-finger-prevention ask called for (see `docs/meta/2026-07-17-manfred-feature-backlog.md`, F4). Same `toggleBoothActive` action and `is_active` flag the board's own pause `Switch` uses — only the friction differs, deliberately: the board's switch is instant + reversible for a quick rush-hour breather, while this is a slower, harder-to-fat-finger path for actually ending the day (`AlertDialog` confirm, then a local `HoldToCloseButton` sub-component requiring a 3-second pointer/keyboard hold — cancels on early release, `hold-fill-bar`/`hold-fill` in `globals.css` for the visual progress) plus a 60-second undo toast (`CLOSE_UNDO_MS`, longer than the board's own `undo_seconds` window since closing is rarer and higher-consequence). Reopening carries none of that risk, so it's a plain instant button. Renders inline from `booth-form.tsx` only when editing an existing booth.
- `menu-editor.dom.test.tsx` — RTL/jsdom tests for `MenuEditor`'s item-level allergen UI (the allergen checkboxes stay hidden behind a collapsed per-item "Advanced" toggle by default, then appear once it's expanded) and for the "Duplicate" action (independent copy, distinct name, carries option groups/allergens over as independent data, disabled at the item cap).
- `menu-editor.tsx` — `MenuEditor({ vendorId, items, onChange, entitlement })`: per-item editor (name, description, `ImageUploader` thumb, price/cost in dollars via `centsToDollarString`/`parseDollarsToCents`, `available` checkbox, an optional sold-out `stock` cap gated by `entitlement.stockCaps` behind a `ProLock`, a "Duplicate" action that deep-clones the item into a fully independent copy — always a starting point, never a shared/live reference, since qkit has no linked modifier groups — and a collapsible `OptionGroupsEditor` section) plus a separate, collapsed-by-default "Advanced" section listing `ALLERGEN_TAGS` checkboxes for allergens always present in the item regardless of customization (distinct from a choice's own allergens in `OptionGroupsEditor`); enforces `canAddMenuItem` against the plan's `maxMenuItems`, showing a `ProLock` once at cap (also disables Duplicate).
- `new/` — create-booth page (renders `BoothForm` with no `initial`).
- `option-groups-editor.dom.test.tsx` — RTL/jsdom tests for `OptionGroupsEditor`: a price input sits next to every choice and is always visible (not behind Advanced), and typing into it updates that choice's `price_delta_cents`; cost and allergen fields stay hidden behind a collapsed per-choice "Advanced" toggle by default, then appear once it's expanded.
- `option-groups-editor.tsx` — `OptionGroupsEditor({ groups, onChange, entitlement })`: generic (not coffee-specific) editor for an item's customization groups — add/remove group, label, single/multi (`ToggleGroup` "Pick one"/"Pick any"), and per-group choices, each with an always-visible price delta input (`price_delta_cents` — every vendor cares about price) plus a collapsed-by-default per-choice "Advanced" toggle revealing a cost delta (`cost_delta_cents`) and `ALLERGEN_TAGS` allergen checkboxes; enforces `canHaveOptionGroups` against `entitlement.maxOptionGroupsPerItem`.
- `page.tsx` — `BoothsPage()` (server, `revalidate = 0`): lists the vendor's booths (`servableBoothIds`/`isBoothPaused` mark which are paused by the plan's active-booth cap), shows an upgrade CTA when `canAddBooth` is false, and renders `BoothList`.
- `payment-section.dom.test.tsx` — RTL/jsdom tests for `PaymentSection`: PayNow emits `{kind:"paynow", payee_name, uen}` on the UEN toggle or `{kind:"paynow", payee_name, mobile}` (always `+65`-prefixed) on the Mobile number toggle, non-digit input stripped and capped at 8 digits, switching the toggle clears the other field, and the toggle starts on Mobile number when the existing config already has one; selecting "No online payment" emits `null`; the "pointer" (payment link/QR image) option defaults to the link field and clears the other field when the sub-mode toggles.
- `payment-section.tsx` — `PaymentSection({ vendorId, value, onChange })`: a `RadioGroup` of three payment kinds — `none` (no online payment), `paynow` (payee name + an explicit UEN/Mobile number `ToggleGroup` — same segmented-control pattern as `pointer`'s own link/QR toggle below, so the two sub-modes in this form look consistent, generates a QR with amount pre-filled — real Singapore UENs always end in a letter check digit, so inferring the kind from a leading `+` let a vendor's bare local mobile number pass validation as a plausible-looking UEN and silently produce a PayNow QR real banking apps rejected; the mobile mode instead shows a fixed, non-editable `+65` prefix (`InputGroup`/`InputGroupAddon`, `@/components/ui/input-group`) with the input accepting only the 8 local digits, so the ambiguity can't arise), `pointer` (a payment link OR an uploaded QR image, mutually exclusive via a `link`/`qr` `ToggleGroup`); treats a reserved `"stripe"` kind as `"none"` in the editor. Each radio card shows only its short label at a glance — the fuller explanation (e.g. `pointer`'s list of supported providers) lives behind an `InfoTooltip` (`@merqo/ui`) instead of a permanently-shown paragraph, matching every other one-more-sentence spot in the app rather than being the one wall-of-text option list; the info button is a sibling of the `<label>`, not nested inside it, so tapping it opens the tooltip without also toggling the radio underneath. The component itself is unchanged by the paykit cutover — it's purely a controlled `PaymentConfig` editor; `actions.ts`'s `saveBooth` is what redirects the write to paykit, and `[boothId]/page.tsx` is what reads it back (via `getVendorConfig`) to build the `value` this form re-opens with, so an existing booth's payee/UEN/mobile/label/link fields now start pre-filled rather than blank. Below the form, a "Manage payments, transactions & refunds in paykit ↗" link opens `${NEXT_PUBLIC_PAYKIT_URL}/dashboard` in a new tab — same fallback default (`https://paykit-sg.vercel.app`) as `src/lib/paykit/client.ts`, always shown regardless of `kind`.
- `printing-section.dom.test.tsx` — RTL/jsdom tests for `PrintingSection`: clicking the switch calls `onChange` with the flipped boolean and a `true` value renders it checked; no printer link/hint shows while `print_enabled` is off; enabling it without a `boothId` (unsaved booth) shows a "save this booth first" hint; enabling it with a `boothId` and `NEXT_PUBLIC_PRINTKIT_URL` set renders a link to printkit's bridge page keyed by that booth id; an unset URL falls back to a "not configured yet" hint.
- `printing-section.tsx` — `PrintingSection({ value, onChange, boothId? })`: a labeled `Switch` row ("Print via printkit" / "Auto-print a label for every QR order placed on this booth." — QR order, not walk-up, since `notifyPrintkit` only fires from the customer-facing `/o/[code]` order flow, never from walk-up order entry), markup copied from `booth-form.tsx`'s own "Default to walk-up order entry" toggle for visual consistency — driving `print_enabled` (migration 0082), the per-booth opt-in gating both `notifyPrintkit`'s order-placement print call (`src/app/o/[code]/actions.ts`) and whether `saveBooth`/`deleteBooth` register this booth's printkit location as active/inactive. When `value` is on, also renders a "Choose the printer for this booth →" link (once `boothId` and `NEXT_PUBLIC_PRINTKIT_URL` are both available — the former only exists once the booth is saved, matching `src/lib/printkit/client.ts`'s own no-fallback-host convention for the latter) to printkit's `/dashboard/bridge?booth=<boothId>`, so a vendor can jump straight to pairing a printer for this specific booth instead of hunting for it in printkit's own dashboard.
- `social-links-section.dom.test.tsx` — RTL/jsdom tests for `SocialLinksSection`: stays off (`null`) with no fields shown by default; enabling the override seeds the fields from `vendorDefaults` and calls `onChange` with them; disabling it clears back to `null`.
- `social-links-section.tsx` — `SocialLinksSection({ value, onChange, vendorDefaults })`: a "Use custom links for this booth" `Checkbox` gating a per-booth override of the vendor's profile-level social links — off (`value: null`) means the booth just inherits `vendorDefaults`; turning it on seeds `SocialLinksFields` (`@/components/social-links-fields`) from those same defaults, so a vendor only has to retype the one link that differs for this booth, not the whole set.
- `working-hours-editor.tsx` — `WorkingHoursEditor({ value, onChange, entitlement })`: daily (single open/close) or weekly (per-weekday `DayWindow`) schedule editor, gated entirely behind `entitlement.autoCloseHours` (shows a `ProLock` card instead when the plan lacks it); converts between modes via `dailyFromWeek`/`weekFromDaily` from `@/lib/hours-editor`.

## Connectivity

`page.tsx` lists booths (`booth-list.tsx`), which links to `new/` and `[boothId]/`, both of which render the shared `booth-form.tsx` (create vs. edit) built from `menu-editor.tsx` (itself embedding `option-groups-editor.tsx`), `working-hours-editor.tsx`, `payment-section.tsx`, `printing-section.tsx`, and `social-links-section.tsx`. `booth-form.tsx` and the `new`/`[boothId]` pages call `saveBooth`/`deleteBooth`/`regenerateShortCode` in `actions.ts`, which enforce the same `@/lib/plan` entitlement caps the editors gate in the UI.
