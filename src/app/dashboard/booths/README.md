# booths

## Purpose

Vendor booth list, the shared create/edit form and its building-block editors, and the server actions that persist a booth under plan entitlements.

## Contents

- `[boothId]/` — edit-booth page for one booth id, plus its printable QR and menu-manager sub-routes.
- `booking-status-section.dom.test.tsx` — RTL tests for `BookingStatusSection`: typing/clearing the input calls `onChange` with the trimmed value or `null`; no status block or "unavailable" text renders while no id is set; an id set with `status: null` shows a quiet "Booking status unavailable right now." message; a real status renders its label, event date, and each of deposit/balance's amount + paid/not-yet-paid state.
- `booking-status-section.tsx` — `BookingStatusSection({ value, onChange, status? })`: a controlled `Input` for a vendor-pasted paykit booking id (event-mode booths only — see `booth-form.tsx`'s gating below), plus a read-only status block (booking status label, event date, deposit/balance amounts via `formatPrice`, and a Paid/Not yet paid mark for each) rendered only when both an id is set and `status` (fetched server-side by `[boothId]/page.tsx` via `getBookingStatus`) is non-null; `status === null` with an id set shows a quiet "unavailable" line instead of an error, matching `getVendorConfig`'s own degrade pattern.
- `actions.test.ts` — vitest suite (mocked Supabase chains, mocked `@/lib/paykit/client`, mocked `@/lib/printkit/client`) covering `saveBooth`'s entitlement enforcement: silent stripping of `hours` on a free-plan save, the active-booth cap (reject activating a 2nd booth) and its `neq` exclusion when re-saving the same booth; the paykit cutover (a set config writes the full config to paykit and only a `{kind}` marker to `booths.payment`, a null config clears the marker without calling paykit, a paykit rejection fails the whole save without writing the booth); printkit location sync (`print_enabled` lands on the row, `registerPrintLocation` is called with `active: true`/`false` to match, and a rejected or `ok:false` call never changes `saveBooth`'s own return value); `deleteBooth`'s own printkit deregistration (`registerPrintLocation` called with `active: false` and the deleted booth's name/id after a successful delete, and a rejected or `ok:false` call never changes `deleteBooth`'s own return value); `saveMenuItems`'s own entitlement enforcement (menu-item cap rejection, option-group cap rejection, silent stripping of per-item `stock` on a free-plan save vs. kept on a stock-cap plan, invalid-id/malformed-item rejection before any DB write, "Booth not found" for a foreign/nonexistent id, and an update matching no row); and `toggleBoothActive`'s invalid-id rejection, unconditional allow when turning off, the same active-booth cap (and `neq` self-exclusion) when turning on.
- `actions.ts` — server actions: `deleteBooth(boothId)` hard-deletes a booth (cascades to its orders per migration 0009), RLS-scoped so a non-owner deletes zero rows, reclaims its Storage images via `removeBoothImages`, and best-effort deregisters the booth's printkit print location (`registerPrintLocation` with `active: false`) so a deleted booth doesn't linger as an active location on printkit's side — never blocks the delete itself; `regenerateShortCode(boothId)` calls the `regenerate_short_code` RPC to rotate the booth's QR token and revalidates the QR page; `saveBooth(input)` validates with `boothFormSchema` (which no longer carries `menu_items` — see the schema's own comment), re-checks entitlement server-side (strips `hours` for plans without `autoCloseHours`), enforces the free-tier single-active-booth cap via a count query, and — the paykit cutover — when `payment` is set, calls `upsertVendorConfig` (`@/lib/paykit/client`) with the full config, failing the whole save on a paykit error; it then inserts or updates the `booths` row (never touching `menu_items`) with `payment` narrowed to a minimal `{kind}` marker via `paymentMarker` (not the full config — see the doc comment on why: `qkit.place_order`, migration 0056, still reads `booths.payment->>'kind'` to decide a new order's `payment_status`, and there is no SQL-side way to ask paykit instead) plus `requires_arrival_confirm`, `walkup_default`, `print_enabled`, and `paykit_booking_id` (none entitlement-gated, and the last stored as-is — no paykit-side validation at write time), and reclaims orphaned booth-banner images (`orphanedImagePaths`) on update; after a successful save it best-effort calls `registerPrintLocation` (`@/lib/printkit/client`) with the booth's id/name and `print_enabled` as `active`, so printkit knows whether this booth's location should currently accept jobs — a failure there is logged and never turns the save into an error, same contract as `notifyPrintkit` in `src/app/o/[code]/actions.ts`. Both call sites share a `syncPrintLocation(vendorId, boothId, label, active, context)` helper, `context` only used to label its own error logs (`"saveBooth"`/`"deleteBooth"`). `saveMenuItems(boothId, items)` is the exclusive write path for `booths.menu_items` (see `menu-manager.tsx`) — validates `menuItemsInputSchema`, re-checks the same menu-item/option-group caps and per-item `stock` stripping `saveBooth` used to apply, then does a scoped `.update({ menu_items })` (RLS `booths_vendor_all`, foreign/nonexistent id → "Booth not found") and reclaims orphaned item-photo images the same way `saveBooth` does. `toggleBoothActive(boothId, active)` is a lightweight sibling that flips only `is_active` — used by both the live board's quick pause `Switch` and this folder's `close-booth-control.tsx`, same active-booth cap check as `saveBooth` when turning on, always allowed when turning off.
- `booth-form.dom.test.tsx` — RTL tests for `BoothForm`'s walk-up-default `Switch` (every other subcomponent it composes is stubbed out — each already has its own dom test file): starts unchecked and submits `walkup_default: false` for a plain new booth, toggling it on submits `true`, `eventMode` pre-checks it and shows a "Recommended" badge (create flow only), an existing booth's saved `true` value round-trips on render, and toggling an existing booth's value off persists on save.
- `booth-form.tsx` — `BoothForm({ vendorId, entitlement, vendorSocialLinks, eventMode?, initial? })` client component: the single create/edit form driving `name`, `image_url`, `is_active`, `hours`, `payment`, `social_links`, `print_enabled` state, composing `WorkingHoursEditor`, `PaymentSection`, `PrintingSection`, `SocialLinksSection`, `BookingStatusSection`, and an `ImageUploader` banner inside `Section` blocks. The "Menu" `Section` never embeds an editor of its own — an existing booth (`initial.boothId` set) shows a read-only item-count summary (`initial.menuItemCount`) linking to the dedicated `[boothId]/menu/` page (see `menu-manager.tsx`), a brand-new unsaved booth shows a "Save this booth to start building its menu" hint instead. `saveMenuItems` needs a real `boothId`, which doesn't exist before the first save — and eagerly creating a draft row before that (so a new booth always has one) was considered and rejected: the free plan caps at 1 **total** booth, not just active ones, so an abandoned draft would permanently eat a free vendor's only slot. ## Connectivity

`page.tsx` lists booths (`booth-list.tsx`), which links to `new/` and `[boothId]/`, both of which render the shared `booth-form.tsx` (create vs. edit) built from `working-hours-editor.tsx`, `payment-section.tsx`, `printing-section.tsx`, and `social-links-section.tsx`. `booth-form.tsx` and the `new`/`[boothId]` pages call `saveBooth`/`deleteBooth`/`regenerateShortCode` in `actions.ts`, which enforce the same `@/lib/plan` entitlement caps the editors gate in the UI. `menu-editor.tsx` (itself embedding `option-groups-editor.tsx`) is no longer composed by `booth-form.tsx` directly — it's rendered by `menu-manager.tsx` instead, reached via `[boothId]/menu/`, whose own save (`saveMenuItems` in `actions.ts`) is the sole write path for `booths.menu_items`.
