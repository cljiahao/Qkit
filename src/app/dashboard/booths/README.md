# booths

## Purpose

Vendor booth list, the shared create/edit form and its building-block editors, and the server actions that persist a booth under plan entitlements.

## Contents

- `[boothId]/` — edit-booth page for one booth id, plus its printable QR sub-route.
- `actions.test.ts` — vitest suite (mocked Supabase chains) covering `saveBooth`'s entitlement enforcement: menu-item cap rejection, option-group cap rejection, silent stripping of `hours`/`stock` on a free-plan save, the active-booth cap (reject activating a 2nd booth) and its `neq` exclusion when re-saving the same booth; and `toggleBoothActive`'s invalid-id rejection, unconditional allow when turning off, the same active-booth cap (and `neq` self-exclusion) when turning on.
- `actions.ts` — server actions: `deleteBooth(boothId)` hard-deletes a booth (cascades to its orders per migration 0009), RLS-scoped so a non-owner deletes zero rows, and reclaims its Storage images via `removeBoothImages`; `regenerateShortCode(boothId)` calls the `regenerate_short_code` RPC to rotate the booth's QR token and revalidates the QR page; `saveBooth(input)` validates with `boothFormSchema`, re-checks entitlement server-side (menu-item cap, option-groups-per-item cap, strips `hours`/per-item `stock` for plans without `autoCloseHours`/`stockCaps`), enforces the free-tier single-active-booth cap via a count query, then inserts or updates the `booths` row (including `requires_arrival_confirm`, not entitlement-gated — every plan may turn it on) and reclaims orphaned images (`orphanedImagePaths`) on update; `toggleBoothActive(boothId, active)` is a lightweight sibling that flips only `is_active` — used by both the live board's quick pause `Switch` and this folder's `close-booth-control.tsx`, same active-booth cap check as `saveBooth` when turning on, always allowed when turning off.
- `booth-form.tsx` — `BoothForm({ vendorId, entitlement, initial? })` client component: the single create/edit form driving `name`, `image_url`, `is_active`, `hours`, `menu_items`, `payment` state, composing `MenuEditor`, `WorkingHoursEditor`, `PaymentSection`, and an `ImageUploader` banner inside `Section` blocks; validates with `boothFormSchema` on submit (sanitizing half-filled option groups first), calls `saveBooth`/`deleteBooth`, and includes a "Danger zone" delete confirmation (`AlertDialog`) when editing. The "Hours & availability" section's active/inactive control differs by mode: a brand-new booth (no `initial.boothId`) gets a plain `Checkbox` (nothing to guard yet — it isn't live); an existing booth gets `CloseBoothControl` instead, a deliberately more guarded close path than the board's own pause switch. Below the hours editor, a "Hold prep until the customer arrives" `Checkbox` drives `requires_arrival_confirm` ("scan-to-start" — for items made fresh per order, like ice cream, where prep can't start until the customer is actually at the counter): when on, `place_order` (migration 0064) inserts new orders at `'pending'` instead of `'preparing'`, and the order-status page shows an "I'm here, start my order" prompt (`OrderStatusPoller`'s pending branch, `confirmArrival`) instead of starting the clock immediately. Walk-up orders (`place_walkup_order`) are unaffected — a vendor keying in a counter order in person has no "customer arrives later" to wait for.
- `booth-list.tsx` — `BoothList({ booths })`: renders each booth as a `Ticket` card (banner image, name, Active/Paused/Off status pill, item count) with Edit / QR (`/dashboard/booths/{id}/qr`) / copy-order-link (`/o/{shortCode}`) actions.
- `close-booth-control.dom.test.tsx` — RTL tests for `CloseBoothControl`: the active state opens a confirm dialog and does nothing on a quick tap-and-release of the hold button; a full 3-second hold calls `toggleBoothActive(id, false)`, notifies the parent, and fires an undo toast whose own action reopens; a failed close/reopen shows an error toast without calling `onChanged`; the paused state reopens on a single instant click, no hold.
- `close-booth-control.tsx` — `CloseBoothControl({ boothId, boothName, isActive, onChanged })` client component: the guarded half of the booth open/close pair Manfred's fat-finger-prevention ask called for (see `docs/meta/2026-07-17-manfred-feature-backlog.md`, F4). Same `toggleBoothActive` action and `is_active` flag the board's own pause `Switch` uses — only the friction differs, deliberately: the board's switch is instant + reversible for a quick rush-hour breather, while this is a slower, harder-to-fat-finger path for actually ending the day (`AlertDialog` confirm, then a local `HoldToCloseButton` sub-component requiring a 3-second pointer/keyboard hold — cancels on early release, `hold-fill-bar`/`hold-fill` in `globals.css` for the visual progress) plus a 60-second undo toast (`CLOSE_UNDO_MS`, longer than the board's own `undo_seconds` window since closing is rarer and higher-consequence). Reopening carries none of that risk, so it's a plain instant button. Renders inline from `booth-form.tsx` only when editing an existing booth.
- `menu-editor.tsx` — `MenuEditor({ vendorId, items, onChange, entitlement })`: per-item editor (name, description, `ImageUploader` thumb, price/cost in dollars via `centsToDollarString`/`parseDollarsToCents`, `available` checkbox, an optional sold-out `stock` cap gated by `entitlement.stockCaps` behind a `ProLock`, and a collapsible `OptionGroupsEditor` section); enforces `canAddMenuItem` against the plan's `maxMenuItems`, showing a `ProLock` once at cap.
- `new/` — create-booth page (renders `BoothForm` with no `initial`).
- `option-groups-editor.tsx` — `OptionGroupsEditor({ groups, onChange, entitlement })`: generic (not coffee-specific) editor for an item's customization groups — add/remove group, label, single/multi (`ToggleGroup` "Pick one"/"Pick any"), and per-group choices; enforces `canHaveOptionGroups` against `entitlement.maxOptionGroupsPerItem`.
- `page.tsx` — `BoothsPage()` (server, `revalidate = 0`): lists the vendor's booths (`servableBoothIds`/`isBoothPaused` mark which are paused by the plan's active-booth cap), shows an upgrade CTA when `canAddBooth` is false, and renders `BoothList`.
- `payment-section.dom.test.tsx` — RTL/jsdom tests for `PaymentSection`: PayNow emits `{kind:"paynow", payee_name, uen}` on the UEN toggle or `{kind:"paynow", payee_name, mobile}` (always `+65`-prefixed) on the Mobile number toggle, non-digit input stripped and capped at 8 digits, switching the toggle clears the other field, and the toggle starts on Mobile number when the existing config already has one; selecting "No online payment" emits `null`; the "pointer" (payment link/QR image) option defaults to the link field and clears the other field when the sub-mode toggles.
- `payment-section.tsx` — `PaymentSection({ vendorId, value, onChange })`: a `RadioGroup` of three payment kinds — `none` (no online payment), `paynow` (payee name + an explicit UEN/Mobile number `ToggleGroup`, generates a QR with amount pre-filled — real Singapore UENs always end in a letter check digit, so inferring the kind from a leading `+` let a vendor's bare local mobile number pass validation as a plausible-looking UEN and silently produce a PayNow QR real banking apps rejected; the mobile mode instead shows a fixed, non-editable `+65` prefix (`InputGroup`/`InputGroupAddon`, `@/components/ui/input-group`) with the input accepting only the 8 local digits, so the ambiguity can't arise), `pointer` (a payment link OR an uploaded QR image, mutually exclusive via a `link`/`qr` `ToggleGroup`); treats a reserved `"stripe"` kind as `"none"` in the editor.
- `working-hours-editor.tsx` — `WorkingHoursEditor({ value, onChange, entitlement })`: daily (single open/close) or weekly (per-weekday `DayWindow`) schedule editor, gated entirely behind `entitlement.autoCloseHours` (shows a `ProLock` card instead when the plan lacks it); converts between modes via `dailyFromWeek`/`weekFromDaily` from `@/lib/hours-editor`.

## Connectivity

`page.tsx` lists booths (`booth-list.tsx`), which links to `new/` and `[boothId]/`, both of which render the shared `booth-form.tsx` (create vs. edit) built from `menu-editor.tsx` (itself embedding `option-groups-editor.tsx`), `working-hours-editor.tsx`, and `payment-section.tsx`. `booth-form.tsx` and the `new`/`[boothId]` pages call `saveBooth`/`deleteBooth`/`regenerateShortCode` in `actions.ts`, which enforce the same `@/lib/plan` entitlement caps the editors gate in the UI.
