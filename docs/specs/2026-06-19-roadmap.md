# QKit improvement roadmap — research-grounded

Date: 2026-06-19
Status: approved-for-implementation

## Research basis (deep-research, SG-first; 24/25 claims verified)

- **Wedge confirmed.** SG/SEA competitors (me&u, Klikit, Qashier, Koomi, HitPay,
  KPay, Rewardly) are integrated POS/payment stacks for **permanent** venues.
  Almost none do **lightweight, app-free, per-event QR _ordering_.** Payment is a
  commodity (~87% cashless) → **ordering + queue + live status is the open lane.**
- **Per-day pricing is structurally correct** — itinerant, footfall-volatile
  vendors (S$14 days, 40% price cuts, ~1-month pasar-malam rotations) want
  pay-only-when-trading. Validates the per-day event pass.
- **Refuted:** "QR payment is universal at bazaars" — false; **cash persists,
  esp. among seniors.** ⇒ the no-account, dead-simple flow matters _more_, not less.
- **Customer UX (Baymard, primary):** keyboard eats ~50% of portrait screen;
  **60% of users can't find guest/no-account checkout**; ~70% baseline cart
  abandonment. Minimize fields, CTA above the keyboard fold, make "no app/account"
  obvious. QR needs a text/adjacent link (Section 508) and anti-tamper handling.
- **Vendor board (KDS research):** glanceable, one-handed, **low-touch** (greasy
  hands); color-code to a **prep-time target** with **ticket-aging alerts** +
  timers; pair color with text/icon (WCAG 1.4.1).
- **Founder admin:** go beyond revenue into **activation → funnel → retention**
  - an in-product **feedback** channel (AARRR / cohort patterns).

### Do NOT pre-build (open questions — validate with pilots)

- Queue/wait-time relief: scan-and-order shortens order-taking, not seating/prep —
  demand unproven for this segment.
- Multi-vendor single-cart (me&u-style): keep the single-booth wedge until an
  event organiser actually asks.
- Aggressive offline mode: confirm real site connectivity first.

## Phases (prioritized)

**Phase 0 — Integrity (build-ready).** Booth-serveability: free = **1 live booth**,
swappable, others paused (not deleted); value-nudge at the limit. Closes the
pay-once-keep-many-booths leak. _High impact / low effort._

**Phase 1 — Customer conversion UX** (strongest evidence). Order page: minimize
fields, sticky submit/cart **above the keyboard fold**, reinforce "order now — no
app, no account"; QR poster shows the order URL as a tappable/text link (508);
resilient order submit (retry) for low signal.

**Phase 2 — Vendor event-day board.** Color-code orders to a prep-time target +
ticket-aging (amber/red as they age) + per-order timer; pair color with text/icon;
bigger tap targets.

**Phase 3 — Founder observability + feedback.** In-product feedback (customer
post-order + vendor) → admin Feedback page. Split `/admin` into Overview ·
Activation funnel · Retention · Feedback · Vendors · Activity.

**Phase 4 — Perf + zero-debt (cross-cutting).** Code-split Recharts, RSC/image
audit; periodic `/code-review`; husky gate keeps format/lint green.

## Phase R — Production readiness (2nd research; do before public launch)

Second deep-research (deploy/ops/observability gaps). Much of QKit's security
posture is already correct (service-role server-only, RLS, security headers in
`next.config.ts`, the service-client RLS fix, pinch-zoom allowed). Remaining gaps:

- **Rate-limit the anonymous order POST** (`placeOrder` is a plain POST anyone can
  spam). _Approach TBD: Upstash ratelimit (external, Vercel-standard) vs a
  DB-backed limiter (no new infra). — needs a call before building._
- **Enable Supabase PITR / backups** (founder toggle in dashboard).
- **Dependency security:** use GitHub **Dependabot _alerts_ + _security updates_**
  (Settings → Code security — fire only on real CVEs). NOT scheduled version
  bumps: those spam weekly PRs that don't fit a solo direct-to-main flow and
  trigger failing Vercel branch previews. Periodic `pnpm audit` covers the rest.
- **CI/CD adds (optional):** `dependency-review` action (PR-only — N/A while
  committing direct to main); a post-deploy smoke test (blocked by the Vercel
  auth gate today).
- **A11y audit:** touch targets ≥44px (WCAG 2.2 AA 2.5.8 min 24px), 4.5:1
  contrast, skeleton loaders for perceived speed. (Pinch-zoom already allowed.)

## Phase 3 refinements (from 2nd research)

- **Retention:** use **rolling retention matched to event cadence** (vendors
  churn _between_ events by design) — NOT weekly cohorts. Do **not** display
  generic "3–8% churn / 40–60% week-1" benchmarks (refuted as unsupported).
- **Feedback:** a FeedbackFin-style lightweight widget wired to a Supabase
  `feedback` table (no heavy third-party) — customer post-order + vendor.

## Quality bar (every phase)

`pnpm check` (prettier + eslint + tsc) green · tests pass · build clean · pure
logic in `src/lib` with unit tests · RLS for authorization · no `any`/debt.
